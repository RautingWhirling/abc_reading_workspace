# 输出格式说明

当前 `run_eval.py` 生成的最终 JSON 采用 `action_schema_v2`，目标是让输出更接近“可执行动作清单”，而不是只给一段自然语言策略描述。

## 顶层结构

```json
{
  "事件名称": "...",
  "输出格式版本": "action_schema_v2",
  "选取数字人id组": ["82945", "85879"],
  "策略概览": {
    "主平台": "weibo_simulated",
    "传播目标": "...",
    "目标圈层": ["泛公众"],
    "传播窗口": {
      "stage_1_launch": "T0 - T+2h",
      "stage_2_engage": "T+2h - T+8h",
      "stage_2_support": "T+2h - T+8h",
      "stage_3_amplify": "T+8h - T+24h"
    },
    "主选节点数": 5
  },
  "82945": {
    "...节点策略..."
  }
}
```

## 设计原则

- `内容发布动作` 负责“发什么、什么时候发、在哪发”。
- `受众互动动作` 负责“点赞、评论、回复、监测”这类面向用户的动作。
- `数字人协同动作` 负责“给哪个数字人点赞、评论、联动转发”。
- `风险控制动作` 负责“何时暂停、何时转人工、何时持续监测”。
- `补充说明` 保留少量文本，用来补充动作背后的语义意图，但不再替代动作本身。

## 当前实现特点

- 发帖正文仍可由 LLM 生成或规则回退生成。
- 互动和协同部分现在以结构化动作数组输出，更适合后续接自动化执行器。
- 动作类型当前主要包括：
  - `publish_post`
  - `publish_followup_post`
  - `publish_support_post`
  - `quote_repost`
  - `monitor_comments`
  - `like_post`
  - `like_comment`
  - `comment_on_post`
  - `reply_comment`
  - `reply_agent_comment`
  - `monitor_sentiment`
  - `pause_dispatch_if_needed`
